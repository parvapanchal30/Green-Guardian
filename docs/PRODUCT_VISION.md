# Product Vision

## One sentence
GreenGuardian is a system that **models biological assets, understands their state, manages their operational lifecycle, and uses intelligence to determine what should happen next.**

## What it is NOT
Not a tree dashboard, not an agriculture dashboard, not a task manager, not an AI chatbot, not a disease-detection app, not a crop recommender. Not `Dashboard + AI chatbot + Task manager`. AI must be *integrated into the operational system*.

## The ladder
What exists? → What is its state? → What is going wrong? → What will happen? → What should we do? → Did it work? → How do we optimize the whole system?

## The loop
REGISTER → MONITOR → OBSERVE → DETECT → UNDERSTAND → CREATE ISSUE → CREATE TASK → TAKE ACTION → MONITOR RESULT → RESOLVE → LEARN/PREDICT → RECOMMEND NEXT ACTION

## Two modes, one platform
- **Green Management** (municipalities, NGOs, campuses, parks): survival, health, growth, canopy, coverage.
- **Agricultural Production** (farms, growers, orchards): growth, health, yield, harvest, revenue.
Both run on the same biological asset graph; mode is configuration (vocabulary, KPIs, lifecycle template, dashboard).

## Three layers
1. **Asset** — what exists
2. **Operations** — what needs to happen
3. **Intelligence** — what should happen next

## Signature features
- **Botanical Issues:** first-class domain objects with lifecycle, evidence, history — not generic tickets.
- **Botanical Operations Agent:** decides what requires attention and converts intelligence into operational actions (recommendations → issues/tasks). Not primarily a chatbot.

## Principles
1. Time-aware state: never overwrite history.
2. Honesty: never present rules as ML, mocks as predictions, or ranges as precision.
3. Operational first: every insight ends in an action someone owns.
4. One model: don't fork agriculture and green management.
5. Serious software: dense, legible, field-usable, accessible.
6. Build the MVP; make the architecture capable of the rest.
